小人会走了，但它会穿墙

大家好，我是「山岚的运维笔记」。

上一篇将坐标搞明白咗，但嗰个小子仲系个钉子户，钉喺 (96,64) 郁都唔郁。呢回畀佢接上键盘。

顺便把一个新手最常犯的毛病当场堵掉：按住不放，人物一路跑飞。

**先别急着写代码**

新手容易犯一个毛病，一上手就在脚本里写「如果按了 W 键，就往上一格」。能跑，真的能跑。

但这条路走不远。等你要加手柄、要加方向键、要做键位设置界面，满屏的键名就得一个个改，改漏一个就是一个 bug。更麻烦嘅系——第日玩家话「我想用左手玩」，你只好干笑。

Godot 的解法叫**输入动作**。你别问「按下 W 这个键」，「玩家想往上走」这件才算一件事。键是键，事是事，中间那层翻译交给输入映射。

打开项目设置，切到「输入映射」：

（图1：项目设置里的「输入映射」面板）

左边一列是动作名，右边是给它绑的键。翻译过来就是：不管玩家按了哪个键，只要它属于 move_up，游戏收到的都只有一句「他要往上走」。

**四个动作，八条绑定**

推箱子只要四个方向，所以我建了四个动作：move_up、move_down、move_left、move_right。

添加不复杂。在「添加新动作」的框里敲名字，回车，动作就有了。然后点它右边那个加号，弹出一个等按键的窗，这时候你按下 W，它自己就记上了。

每个动作我都绑了两个键，WASD 一套、方向键一套：

（图2：四个动作，每个都绑了两个键）

为什么非要绑两套？因为我这双手写代码时离不开 WASD，可坐在沙发上的时候又只想按方向键。多绑一个又唔使钱，点解唔绑。

顺便说那个**死区**。它是给摇杆用的——摇杆不像按键，只有 0 和 1，它能到 0.37 这种中间值。死区就是「推得不够狠，当没推」的门槛。键鼠用不上，留着 0 就对了。

说个坑。我一开始没走面板，直接去改工程配置文件，照着老习惯写了两段重复的段头。Godot 一声不吭地把它们全忽略了，面板空空如也，我还以为引擎坏了。后来才明白，那得写成字典格式。白折腾半天——所以你要是也用命令行改配置，记住它有它自己的规矩。

**接住按键**

配好了，回到脚本。开一个 _unhandled_input，里面就是四个判断，每个判断给一个方向。

有个细节别搞反：判断的时候传的是**动作名**，不是键名。哪天玩家想把上键改成 I，你一行代码都不用动，去面板上换个绑定就完事。这就是前面那层翻译的回报。

还有个负号。上一篇说过 Y 轴朝下，所以「往上」是**减** y。我第一次写嗰阵顺手写咗正一，结果按上键人物往下窜，呆咗三秒。

**差一个 just，差很多**

这是今天最值钱的一句话。

写在 _unhandled_input 里的 event.is_action_pressed，只在你刚按下那一瞬间那个事件上返回 true。按住不放，系统不会一直塞新事件给你。所以——按一下，走一格。

要是你图省事，在 _process 里轮询「有没有按下」，那就有意思了。_process 一秒钟跑六十次，你手指按住半秒，它就给你走三十格。呢个唔系推箱子，呢个系弹射起步。

正确的轮询写法，函数名里多带一个 just：is_action_just_pressed。它是「这一帧刚按下」，而且一帧只成立一次。名字里多这一个词，性质就完全不同。

我建议你两个都写一遍，亲手按住不放感受一下，比看十篇文章有用。

**让它一格一格挪**

这里有个坑得先讲，不然你照着写完会一脸问号。格子号只是我们自己记的一个数，小人真正站哪里，看的是它自己的 position 属性，这俩不是一回事。你只将格子号加一、唔去动 position，结果就系黄框一格一格跑得欢，小人喺原地纹丝不动——我第一次就系咁呆咗喺度。

所以算完格子，还得把像素位置写回去。直接赋值能走，但是瞬间到位，硬跳看着像掉帧；改用补间（Tween）把这段位移摊到 0.12 秒就顺眼了，够短，不拖沓；又不是零，眼睛跟得上。

**还差一块：它现在能穿墙**

能动了，但小人而家系个会穿墙嘅。往左按十下，佢就从画面左边消失咗。

下一篇给它加上地图和边界，让它知道哪里能走、哪里不能走。

**最后**

今天三件事。动作名要和键名分开，配在输入映射里。接收按键用 _unhandled_input 配 event.is_action_pressed。想轮询就用 is_action_just_pressed，别用没 just 的那个。
